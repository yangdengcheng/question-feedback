# 问题反馈工单平台 · 使用说明书

> 适用对象：客户、数据维护、研发、测试、研发主管、管理员
> 用途：内部培训与日常使用参考

---

## 一、平台简介

问题反馈工单平台用于统一收集、流转、跟踪和闭环各类问题（Bug / 使用问题），替代以往口头、群聊反馈的方式，做到**事事有记录、流程可追踪、进度可查询**。

平台核心能力：

- **工单管理**：提交、分配、转交、评论、附件、状态流转、单条/批量删除、全程操作留痕。
- **工单看板**：按状态统计、快速查看最近工单。
- **消息通知**：站内通知 + 浏览器桌面通知，关键节点自动提醒。
- **工具包中心**：脚本/工具包的发布、说明文档、版本管理、下载与删除。
- **服务监控**：前台导航直达，仅研发相关角色可见。
- **后台管理**：用户、工单、字典统一维护。

## 二、角色与权限总览

| 角色 | 代码 | 主要权限 |
| --- | --- | --- |
| 客户 | `customer` | 创建/查看自己的工单；确认解决、重新打开；下载工具包 |
| 数据维护 | `data_maintenance` | 查看内部工单；处理被分配的工单；转交 |
| 系统开发 | `developer` | 处理工单、转交；维护工具包（新建/发布/上下架） |
| 测试 | `tester` | 处理工单、转交 |
| 研发主管 | `dev_lead` | 查看全部工单；处理/转交；维护工具包；接收新工单通知；可进入后台管理 |
| 管理员 | `admin` | 全部权限 + 后台管理（用户/工单/字典）；维护工具包 |

角色分组说明：

- **内部角色**：数据维护、系统开发、测试、研发主管、管理员。内部角色可参与工单处理与转交。
- **工具包维护者**：系统开发、研发主管、管理员。可新建/编辑工具包、发布版本、上下架。
- **管理员**：管理员 + 研发主管可进入「后台管理」。

> 通过页面右上角「注册」入口自助注册的账号默认为**客户**角色；内部角色由管理员在后台分配。

## 三、登录与账号

1. 打开平台地址，进入登录页。
2. 输入账号（用户名/拼音）与密码，点击「登录」。
3. 首次使用的客户可点击「注册」自助创建账号（默认客户角色）。
4. 初始密码由管理员统一发放，登录后请注意保管。
5. 右上角头像菜单可「退出登录」。

## 四、工单模块

### 4.1 工单列表（首页）

- 进入平台默认打开工单列表。
- 支持按 **状态 / 类型 / 优先级** 筛选，按 **关键词** 搜索标题。
- 数据范围因角色而异：
  - 客户：仅看到**自己创建**的工单；
  - 研发主管 / 管理员：看到**全部**工单；
  - 其他内部角色：看到**自己创建 + 分配给自己**的工单。

### 4.2 创建工单

1. 点击「新建工单」。
2. 填写 **标题**（必填）、**详细描述**、**类型**（Bug / 使用问题）、**优先级**（低 / 中 / 高）。
3. 可上传附件（截图、日志等）辅助说明。
4. 提交后工单编号自动生成，状态为「待处理」，并自动通知研发主管与管理员。

### 4.3 工单详情

详情页包含：

- **基本信息**：编号、类型、优先级、状态、创建人、处理人、时间。
- **描述与附件**：问题描述及上传的附件，可下载查看。
- **流转记录**：创建、状态变更、转交等全过程留痕，含操作人与说明。
- **评论区**：创建人与内部人员可评论沟通，评论会通知相关人。

### 4.4 状态流转规则

工单状态共四种：**待处理 → 处理中 → 已解决 → 已关闭**。

| 操作人 | 允许的流转 |
| --- | --- |
| 内部角色 | 可在四种状态间流转（需为处理人/创建人/主管/管理员） |
| 客户（本人工单） | 已解决 → 已关闭（确认解决）；已解决 → 处理中（未解决退回）；已关闭 → 处理中（重新打开） |

典型闭环流程：

1. 客户提交 → **待处理**；
2. 内部人员认领/被分配、转交 → **处理中**；
3. 处理完成 → **已解决**，通知客户；
4. 客户确认 → **已关闭**；若未解决可退回 **处理中**。

### 4.5 转交工单（仅内部）

1. 在工单详情选择「转交」。
2. 选择目标处理人（内部人员），**必须填写转交说明**，可附附件。
3. 转交后处理人变更；若原状态为「待处理」自动变为「处理中」，并通知新处理人。

### 4.6 工单看板

- 顶部四张状态卡片：待处理 / 处理中 / 已解决 / 已关闭，点击可跳列表。
- 下方「最近工单」展示最近更新的 8 条。
- 统计口径：内部角色统计**分配给我的**，客户统计**我创建的**。

## 五、通知模块

### 5.1 通知类型与触达对象

| 事件 | 通知对象 | 内容示例 |
| --- | --- | --- |
| 新工单创建 | 全体研发主管 + 管理员 | 新工单 GD20260731001：xxx |
| 新评论 | 工单创建人 + 当前处理人 | xxx 在工单中发表了新评论 |
| 状态变更 | 工单创建人 | 工单状态变更为「已解决」 |
| 被分配/转交 | 新处理人 | 您被分配了工单 xxx |

### 5.2 站内通知

- 顶栏铃铛显示**未读数**，每 30 秒自动刷新。
- 点击铃铛进入「通知中心」，可查看未读通知、**全部已读**。
- 点击单条通知可跳转到对应工单。

### 5.3 浏览器桌面通知

- 首次使用会请求通知权限，请选择「允许」。
- 有新通知时，系统右下角弹出桌面提醒；**通知常驻，需手动点击或关闭**，点击可跳转对应工单。
- 桌面通知依赖浏览器「安全上下文」：**HTTPS 或 localhost 下自动可用**。

#### HTTP 环境开启桌面通知（内网试运行）

若平台以 `http://` 部署，Chrome 默认不开放桌面通知，可手动配置：

1. 地址栏打开 `chrome://flags/#unsafely-treat-insecure-origin-as-secure`；
2. 找到 **Insecure origins treated as secure**；
3. 填入完整来源（含协议、IP/域名、端口，不含路径），如 `http://58.221.192.245:3333`，多个用英文逗号分隔；
4. 设为 **Enabled**，点击 **Relaunch** 重启浏览器；
5. 重新打开平台，地址栏左侧图标 → 网站设置 → 通知 → 选择「允许」。

> 该配置为每台电脑各自设置，适合小范围试运行；大范围使用建议部署 HTTPS。

## 六、工具包模块

### 6.1 浏览与下载（所有人）

- 「工具包」页按省份/分类浏览工具包列表。
- 进入详情可查看 **说明文档**（Markdown 渲染，含图片）、**版本历史**。
- 点击「下载最新版本」或指定版本下载脚本文件。

### 6.2 维护者操作（开发/主管/管理员）

- **新建工具包**：填写名称、省份、分类、简介、说明文档（支持粘贴/上传图片）。
- **编辑信息与说明**：修改基础信息和说明文档。
- **发布新版本**：填写版本号、上传 `.js` 文件、填写更新说明。
- **上架/下架**：控制工具包对客户是否可见。
- **删除版本**：在版本历史中可删除指定版本（含文件）。删除的是最新版本时，自动回退到次新版本。

## 七、后台管理（管理员 + 研发主管）

### 7.1 用户管理

- 查看用户列表，搜索用户。
- 修改用户**角色**、**启用/停用**账号。
- 停用后该用户无法登录。

### 7.2 工单管理

- 查看全平台工单，协助分配与跟进。
- **单项删除**：每行操作区「删除」按钮，确认后级联清除评论/附件/通知/日志。
- **批量删除**：勾选多条后点击筛选栏右侧「批量删除（N）」，统一删除。
- 删除操作不可恢复，请谨慎操作。

### 7.3 字典管理

- 维护工具包使用的 **省份** 与 **分类** 字典，支持增删改与启用/停用。

## 十、常见问题（FAQ）

1. **为什么看不到别人的工单？**
   客户仅能查看自己创建的工单；普通内部角色仅能看到自己创建或被分配的工单。研发主管/管理员可看全部。

2. **为什么收不到桌面通知？**
   检查通知权限是否为「允许」；若为 HTTP 部署，需按 5.3 配置 Chrome。站内通知（铃铛）不受影响。

3. **工单已解决但问题还在，怎么办？**
   客户在工单详情选择「重新打开/退回处理中」，状态回到处理中并继续跟进。

4. **转交工单为什么必须填说明？**
   转交说明会写入流转记录，便于追溯交接原因，故为必填。

5. **忘记密码/账号被停用？**
   联系管理员在后台重置或启用。
